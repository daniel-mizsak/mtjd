# AGENTS.md

## Policies

- When adding or updating code, inspect similar existing solutions and match their structure, logic, and variable naming where applicable.
- Do not assume existing patterns are best practices. Flag outdated idioms or design weaknesses when they have a concrete impact on correctness,
  maintainability, security, or testability. Explain the impact and suggest a specific improvement.
- During editing and review, keep changes directly related to the task. Modify unrelated files only with explicit user permission.
- Only run read-only Git commands. Any Git operation that changes repository state requires explicit user permission. Harness approval does not count.
- Add tests for new features only when asked.
